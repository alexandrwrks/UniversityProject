# Проверка третьей лабораторной

Источник требований: «ООП C# — Задание 3 — Агрегация», обязательная часть, страницы 3–10. Макеты Carts и Orders просмотрены непосредственно на страницах 5 и 8.

| Требование | Реализация |
| --- | --- |
| Cart.Items и сумма Amount без сеттера | Model/Cart.cs; сумма считается циклом; null нормализуется в пустой список |
| Одна корзина на покупателя | Customer.Cart создаётся в конструкторе и имеет только геттер |
| Заказы покупателя | Customer.Orders: отдельный пустой список для каждого покупателя |
| Семь статусов | New, Processing, Assembly, Sent, Delivered, Returned, Abandoned |
| Order: Id, дата, адрес, товары, сумма | Id и CreationDate только для чтения; Amount вычисляется по текущим ценам |
| Агрегация товаров | Cart и Order хранят исходные Item, а не копии товаров |
| Carts: выбор покупателя, добавление/удаление/очистка | Реализовано в отдельной вкладке по макету |
| Create Order | Новый Order с New, Id, датой и адресом; отдельный список товаров; очистка корзины |
| RefreshData и обновление при переходе | Обработчик SelectedIndexChanged в MainForm |
| Orders: сводные заказы покупателей | Customers, Orders, UpdateOrders и RefreshData |
| Шесть столбцов таблицы | Id, Created, Customer Full Name, Delivery Address, Amount, Order Status |
| Ограничения таблицы | Только чтение, одна строка, запрещены добавление, удаление, перестановка столбцов, сортировка и изменение высоты строк |
| Панель выбранного заказа | AddressControl в режиме ReadOnly; редактируется только Status |
| UML | Practics3.drawio и PNG; композиции и агрегации подписаны кратностями |

## Проверка реализации

Сборка приложения и проверочного проекта — без ошибок и предупреждений. Все 110 проверок прошли. Из них проверки третьей работы покрывают пустые/null-списки, повторяющиеся товары, общие ссылки, сохранение содержимого заказа после очистки корзины, копирование адреса, независимые корзины и заказы покупателей, начальные Id заказа и статусы, обновление вкладок, смену статуса, пересчёт после изменения цены и удаление объектов из каталога.

При проверке исправлено событие выбора заказа: панель обновляется по CurrentCellChanged, когда новая текущая строка уже определена. Выбранный заказ связан со строкой через Tag, а не через числовой индекс.

Обе новые вкладки отрисованы и визуально сопоставлены с макетами. Проверены размеры окна 820×490 и 1100×730; сумма заказа остаётся видна в маленьком окне, таблица поддерживает горизонтальную прокрутку. При выборе пустых данных действия блокируются, панель очищается. Конструктор самой Visual Studio и другие масштабы Windows вручную не проверялись.

## Принятые решения

- Ветка Tasks/3_agregation создана от завершённой Tasks/2_composition, поскольку develop отсутствует.
- Сохранены отдельные последовательности Id товаров и покупателей, как ранее запросил пользователь. У заказов теперь своя последовательность с 1.
- Order получает копию адреса, но исходные объекты Item. Это сохраняет адрес на момент оформления и демонстрирует требуемую агрегацию товаров.
- Дополнительные задания на страницах 11–12 не включены: генерация заказов, OrderControl, сохранение/загрузка, история статусов, поиск и сортировка.
